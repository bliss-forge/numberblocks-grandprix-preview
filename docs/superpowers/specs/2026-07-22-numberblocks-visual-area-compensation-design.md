# 캐릭터 보이는 면적 자동 보정 설계

## 목표

- 18처럼 길고 좁은 캐릭터도 6처럼 작은 숫자 캐릭터보다 보이는 몸체 면적이 확실히 크게 표시되게 한다.
- 기존 숫자 구간 배율은 유지하면서 캐릭터의 블록 배열 형태만 추가 보정한다.
- 1~10 캐릭터의 현재 크기와 이미지 자산은 변경하지 않는다.

## 선택한 방식

캐릭터 PNG를 다시 생성하거나 150개별 수동 배율표를 만들지 않는다. 이미 `NUMBERBLOCKS[number]`에 있는 `rows`와 `cols`를 사용해 블록 몸체의 화면상 밀도를 추정하고, 세로 또는 가로로 길어 면적이 작아 보이는 11 이상 캐릭터에만 자동 보정치를 적용한다.

고정된 모양 분류만 사용하는 방식보다 11과 18처럼 세로 비율이 다른 캐릭터를 구분할 수 있고, PNG 알파 픽셀을 런타임에 읽는 방식보다 단순하고 안정적이다.

## 보정 공식

블록 배열의 긴 변을 `max(rows, cols)`라고 할 때 보이는 면적의 대푯값은 다음과 같다.

```text
배치 밀도 = number / max(rows, cols)²
기준 밀도 = 2 / 3
형태 보정 = sqrt(기준 밀도 / 배치 밀도)
```

- 숫자가 1~10이면 형태 보정은 항상 `1`이다.
- 11 이상에서는 형태 보정을 최소 `1`, 최대 `1.75`로 제한한다.
- 일반 화면의 최종 배율은 `숫자 구간 배율 × 형태 보정`이며 최대 `2.2`를 넘지 않는다.
- 밀도가 기준보다 높은 넓은 캐릭터는 축소하지 않고 형태 보정 `1`을 사용한다.

18은 2×9 배열이므로 배치 밀도는 `18 / 9² = 0.222...`이고 형태 보정은 약 `1.732`이다. 11~20 구간 배율 `1.2`와 결합한 최종 배율은 약 `2.08`이다. 이때 추정 몸체 면적은 6보다 약 44% 크게 되어 화면에서도 크기 차이가 분명해진다.

## 화면 적용

- `src/app-behavior.mjs`에 숫자·행·열을 받아 형태 보정값을 반환하는 순수 함수를 둔다.
- `src/app.mjs`의 공통 `character()` 함수가 모든 캐릭터에 `--shape-scale` CSS 변수를 설정한다.
- `styles.css`는 기존 `--number-scale`과 새 `--shape-scale`을 곱하고 일반 화면 상한 `2.2`를 적용한다.
- 더하기·빼기·곱하기의 피연산자, 세기 친구, 정답 축하 캐릭터가 모두 같은 `character()` 경로를 사용하므로 별도 장면별 계산을 추가하지 않는다.
- `data-shape`는 기존 축하 장면의 최대 너비·높이 선택에 계속 사용하며 새 면적 공식의 입력으로 사용하지 않는다.

## 작은 화면 상한

`@media (max-width: 900px) and (max-height: 500px)`에서는 전체 노출과 조작 가능성을 우선한다.

| 숫자 범위 | 낮은 가로 화면 최종 상한 |
|---|---:|
| 1~10 | 1.0배 |
| 11~20 | 1.1배 |
| 21~50 | 1.15배 |
| 51~100 | 1.2배 |
| 101~150 | 1.25배 |

일반 모바일 세로 화면에는 형태 보정을 그대로 적용하되 최종 배율 `2.2` 상한을 유지한다.

## 안전 동작

- 잘못된 숫자나 0 이하의 행·열이 전달되면 형태 보정 `1`을 반환해 기존 표시를 유지한다.
- 계산 결과가 유한한 숫자가 아니면 형태 보정 `1`을 사용한다.
- 음성, 문제 생성, 정답 판정, 키보드 및 모바일 숫자판 동작은 변경하지 않는다.
- 이미지 자산과 렌더링 스크립트는 수정하지 않는다.

## 검증

- 1~10은 형태 보정 `1`인지 단위 테스트한다.
- 18의 형태 보정이 `sqrt(3)`이고 최종 배율이 약 `2.08`인지 검사한다.
- 넓고 밀도가 높은 20은 형태 보정 `1`을 유지하는지 검사한다.
- 일반 화면 최종 배율 상한 `2.2`와 낮은 가로 화면의 구간별 상한을 CSS 계약 테스트로 검사한다.
- 18과 6 PNG의 실제 불투명 몸체 영역에 최종 배율을 적용했을 때 18의 보이는 면적이 더 큰지 회귀 테스트한다.
- 1280×720의 `18 − 6`, 390×844의 큰 수 장면, 640×360의 상한 장면을 브라우저에서 확인한다.
- 전체 자동 테스트를 실행해 기존 게임·음성·입력 동작의 회귀가 없는지 확인한다.

## 완료 기준

- 18은 6보다 보이는 몸체 면적이 확실히 크다.
- 1~10의 기존 크기는 바뀌지 않는다.
- 11~150의 길고 좁은 캐릭터가 수동 목록 없이 자동 보정된다.
- 일반 화면은 최종 2.2배, 낮은 가로 화면은 구간별 1.0~1.25배 상한을 지킨다.
- 캐릭터 팔다리와 장식, 수식, 답 칸, 숫자판이 잘리거나 서로 가리지 않는다.
