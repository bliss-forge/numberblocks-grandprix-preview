# 숫자 크기 비례 확대 설계

## 목표

- 11 이상 캐릭터가 1~10 캐릭터보다 작게 보이는 문제를 해결한다.
- 숫자가 커질수록 블록 수가 많다는 사실이 화면 크기에서도 분명하게 느껴지게 한다.
- 기존 1~10 캐릭터 크기는 변경하지 않는다.

## 배율

| 숫자 범위 | 화면 배율 |
|---|---:|
| 1~10 | 1.0배 |
| 11~20 | 1.2배 |
| 21~50 | 1.4배 |
| 51~100 | 1.6배 |
| 101~150 | 1.8배 |

- 일반 데스크톱과 모바일 화면에는 위 배율을 그대로 적용한다.
- 덧셈·뺄셈·곱셈의 두 캐릭터 장면, 세기 장면, 정답 축하 장면에 같은 구간 규칙을 사용한다.
- 예를 들어 `20 − 6`에서는 20이 6보다 더 크게 보여야 한다.

## 낮은 화면 안전 제한

- `max-height: 500px`인 가로 화면에서는 배율보다 전체 캐릭터 노출을 우선한다.
- 캐릭터가 무대, 식, 답 칸, 숫자패드를 침범하지 않도록 최대 높이와 최대 너비로 제한한다.
- 제한된 화면에서도 숫자 구간의 상대적인 크기 순서는 가능한 범위에서 유지한다.
- 캐릭터의 팔다리와 장식이 잘리면 안 된다.

## 구현 구조

- 기존 세 단계 `base / medium / large`를 다섯 단계로 확장한다.
- 숫자에서 단계 이름을 선택하는 순수 함수는 `src/app-behavior.mjs`에 둔다.
- 실제 배율과 반응형 제한은 `styles.css`의 `data-size-band` 규칙으로 관리한다.
- 이미지 자산 자체는 다시 생성하지 않는다.

## 검증

- 경계값 10/11/20/21/50/51/100/101/150의 단계 선택을 단위 테스트한다.
- CSS에 정확한 1.0/1.2/1.4/1.6/1.8 배율이 있는지 계약 테스트한다.
- 1280×720에서 `20 − 6`의 20 캐릭터가 6보다 큰지 실제 경계 상자로 확인한다.
- 390×844에서 두 캐릭터와 식·답 칸·숫자패드가 겹치지 않는지 확인한다.
- 640×360에서 캐릭터 전체가 무대 안에 들어오는지 확인한다.
- 전체 자동 테스트를 실행하고 기존 음성·입력·캐릭터 자산 동작의 회귀가 없는지 검사한다.

## 완료 기준

- 1~10의 기존 화면 크기가 유지된다.
- 11 이상은 지정된 구간 배율로 커진다.
- `20 − 6`에서 20이 6보다 시각적으로 크다.
- 매우 낮은 화면에서도 캐릭터가 잘리거나 다른 조작 요소와 겹치지 않는다.
