# 넘버블럭스 두 동네 안전길 재설계

## 목표

기존 길찾기 지도를 실제 동네처럼 보이는 `동네 | 중앙 2차선 도로 | 동네·학교`
구조로 교체한다. 3~5세 어린이가 골목 우회, 움직이는 자전거·킥보드 피하기,
신호를 보고 횡단보도 건너기를 한 흐름으로 학습하게 한다.

완료 기준은 다음과 같다.

- 전체 지도는 가로 `14 : 4 : 14` 비율의 두 동네와 중앙 도로로 보인다.
- 골목은 1칸, 일반 보행길은 2칸, 횡단보도는 2칸 너비다.
- 각 동네에는 위·아래를 연결하는 세로 골목이 2개씩 있다.
- 중앙 도로에는 가로 방향 횡단보도가 위·아래 2곳 있다.
- 맨홀, 공사장, 자전거와 킥보드가 서로 다른 안전 행동을 가르친다.
- 플레이어는 가능한 동안 화면 중앙에 유지되어 진행 방향을 볼 수 있다.
- 랜덤 배치에서도 모든 친구와 학교에 도달하는 안전 경로가 존재한다.
- 충돌, 감점, 출발점 복귀와 게임 오버는 없다.

## 확정된 선택

- 기존 모델을 확장하는 단일 연속 지도 방식이다.
- 지도는 32×16칸이며 가로 구역은 왼쪽 14칸, 도로 4칸, 오른쪽 14칸이다.
- 중앙 도로 4칸은 위로 가는 차선 2칸과 아래로 가는 차선 2칸이다.
- 왼쪽 동네에서 2~5 친구를 먼저 만나고, 도로를 건넌 뒤 오른쪽 동네에서
  6~10 친구를 만나 학교에 도착한다.
- 킥보드와 자전거는 지정된 도로변 보행길 구간을 천천히 왕복한다.
- 아이가 있는 칸으로 이동체가 진입하지 않는다.
- 숫자 친구와 장애물은 검증된 후보 칸 안에서 랜덤 배치한다.

## 지도 구조

### 가로 구역

- `x=0..13`: 왼쪽 생활 동네
- `x=14..17`: 중앙 세로 2차선 도로
- `x=18..31`: 오른쪽 학교 동네

두 차선은 중앙선과 진행 방향 화살표로 구분한다. 차량은 차도 밖으로 나오지
않고, 보행자와 넘버블럭스 친구는 일반 차도에 진입할 수 없다.

### 보행망

각 동네에는 2칸 너비의 가로 보행길 2개와, 1칸 너비의 세로 골목 2개를 둔다.
세로 골목은 위·아래 가로 보행길을 연결한다. 보행길은 밝은 베이지색 포장,
낮은 경계석과 건물 출입구로 표현한다. 차선, 중앙선과 아스팔트 무늬를 사용하지
않아 차도와 혼동되지 않게 한다.

중앙 도로를 가로지르는 횡단보도는 위·아래 가로 보행길과 같은 높이에 2곳을
둔다. 각 횡단보도는 세로 높이 2칸이며 도로의 4칸 전체를 가로 방향으로 잇는다.
두 횡단보도는 같은 보행 신호를 사용해 어린이가 서로 다른 신호를 동시에 판단할
필요가 없게 한다.

### 장소와 친구

- 왼쪽: 우리 집, 어린이집, 상가, 공원과 2~5 친구
- 오른쪽: 도서관, 정류장, 가게, 학교와 6~10 친구

친구는 건물 앞이나 보행길의 안전 후보 칸에만 놓는다. 2~5 친구를 모두 만나기
전에는 어느 횡단보도를 사용해도 오른쪽 동네로 진입할 수 없고, 다음 친구를 먼저
만나도록 안내한다. 2~5를 모두 만나면 위·아래 횡단보도 중 가까운 곳을 선택해
건널 수 있다.

## 교통과 횡단보도

기존 신호 주기를 유지한다.

- `vehicle-go` 5초: 차량 이동, 보행자 빨간불
- `vehicle-clearance` 1초: 차량 정지선 정렬
- `pedestrian-go` 7초: 차량 정지, 두 횡단보도 통행 가능
- `pedestrian-clearance` 1초: 새 진입 금지, 횡단 중인 플레이어만 이탈 가능

보행자 초록불 종료 2초 전에는 새 횡단을 시작하지 않는다. 두 차선의 자동차는
보행자 초록불에 각 횡단보도 정지선 앞에서 멈춘다. 차량 그림은 진행 방향에 맞춰
회전하며 차선 안에서만 순환한다.

## 장애물과 움직이는 이동체

### 열린 맨홀

맨홀은 2칸 너비 보행길 중 한 칸만 막는 정적 장애물이다. 같은 줄의 옆 칸으로
피해 지나갈 수 있다. 어두운 원형 뚜껑, 테두리와 내부 격자 무늬를 크게 표시하고
잘못 진입하면 `맨홀을 피해 옆으로 가요`라고 안내한다.

### 공사 중 골목

공사장은 1칸 너비 세로 골목 하나의 연결 구간 전체를 막는다. 같은 동네의 다른
세로 골목은 반드시 열어 두어 위·아래 길을 우회할 수 있게 한다. 주황·흰색 차단막,
안전 고깔과 공사 표지를 골목 폭보다 크게 보여 준다.

### 킥보드와 자전거

킥보드와 자전거는 도로변의 2칸 너비 보행길에 정의된 짧은 순찰 구간을 왕복한다.
한 칸을 약 0.9~1.2초에 이동해 아이가 방향을 보고 피할 시간을 준다.

- 아이는 위·아래 두 줄 중 비어 있는 줄로 피할 수 있다.
- 아이가 이동체가 있는 칸으로 가려 하면 위치를 유지하고 기다리거나 옆줄로
  피하라는 안내를 받는다.
- 이동체의 다음 칸에 아이가 있으면 이동체가 최소 0.6초 멈춘 뒤 반대 방향으로
  돌아간다.
- 이동체는 아이와 같은 칸을 점유하지 않고, 감점이나 충돌 애니메이션을 만들지
  않는다.

킥보드와 자전거는 이모지가 아니라 큰 평면 일러스트로 그린다. 바퀴, 손잡이,
프레임과 진행 방향이 한눈에 보이게 하고 느린 바퀴 회전과 좌우 흔들림을 적용한다.

## 안전 랜덤 배치

매 게임 시작 시 난이도별 후보 목록에서 친구와 장애물 위치를 선택한다. 전체
격자에서 무작위 좌표를 뽑지 않고, 역할과 안전 조건이 표시된 후보 슬롯만 사용한다.

- 친구 후보: 해당 번호의 동네 안에 있는 건물 앞·보행길 안전 칸
- 맨홀 후보: 옆줄이 비어 있는 2칸 보행길
- 공사 후보: 같은 동네의 다른 세로 골목이 열려 있는 골목 구간
- 이동체 후보: 횡단보도, 친구와 건물 출입구를 침범하지 않는 왕복 구간

배치 후 1에서 10까지 순서대로 친구를 만나고 학교에 도달하는 경로를 검증한다.
검증에 실패하면 최대 20번 다시 선택한다. 모두 실패하면 테스트된 고정 안전 배치를
사용한다. 랜덤 시드는 한 번의 게임 동안 유지되어 화면을 다시 그릴 때 위치가
바뀌지 않는다.

난이도별 요소 수는 다음과 같다.

- 쉬움: 맨홀 1개, 움직이는 이동체 1개, 공사 없음
- 차근차근: 맨홀 1개, 공사 골목 1곳, 이동체 1개
- 도전: 맨홀 최대 2개, 공사 골목 1곳, 킥보드와 자전거 각 1개

## 카메라

카메라는 플레이어가 지도 가장자리에 가까운 경우를 제외하고 플레이어를 뷰포트
정중앙 셀에 유지한다. 기존처럼 넓은 중앙 안전 영역을 벗어난 뒤 움직이는 방식은
사용하지 않는다. 유효 이동 한 칸마다 카메라 목표점을 즉시 갱신하고 140~180ms의
짧은 보간만 적용한다.

- 데스크톱: 기본 7×5칸 이상 표시, 플레이어 앞쪽 최소 3칸 확보
- 모바일: 5×5칸 표시, 플레이어 앞쪽 최소 2칸 확보
- 지도 가장자리: 카메라만 경계에 고정하고 플레이어는 가능한 길 끝까지 이동
- 카메라 애니메이션 중에도 다음 한 칸 입력을 받을 수 있음

화면 밖 다음 친구 방향 화살표와 막혔을 때 표시되는 앞 3칸 유도선은 유지한다.

## 그림과 애니메이션

자동차, 자전거, 킥보드, 맨홀과 공사장은 배경보다 높은 대비와 흰색 외곽선을
사용한다. 실제 칸보다 약간 크게 보이되 충돌 판정 칸은 바꾸지 않는다.

- 자동차: 차체, 유리, 앞뒤와 네 바퀴가 보이는 위에서 본 평면 그림
- 자전거: 두 바퀴와 프레임, 핸들 방향이 구분되는 옆모습
- 킥보드: 두 바퀴, 발판과 긴 손잡이가 구분되는 옆모습
- 맨홀: 원형 테두리와 격자, 열린 공간의 어두운 내부
- 공사장: 차단막, 고깔과 `공사중` 표지

움직임은 위치 변화를 설명하는 수준으로 제한하고 과도한 튕김, 회전과 번쩍임을
사용하지 않는다. `prefers-reduced-motion`에서는 바퀴 회전과 장식 흔들림을 끄고
칸 단위 위치 변화만 유지한다.

## 상태와 구성 요소

### `src/safety-route-model.mjs`

- 32×16 지도와 14:4:14 구역 정의
- 1칸 골목, 2칸 보행길·횡단보도 그래프
- 후보 슬롯 기반 랜덤 배치와 연결성 검증
- 정적 장애물, 이동체 점유와 플레이어 우선 규칙
- 친구 수집 순서와 두 횡단보도 통행 조건

### `src/safety-route-scene.mjs`

- 좌우 동네, 보행 골목, 중앙 2차선과 두 횡단보도 렌더링
- 가시성 높은 평면 안전 요소 그림
- 이동체 방향, 정지와 반전 상태 노출
- 카메라 월드와 목표 방향·유도선 표시

### `src/safety-route-camera.mjs`

- 플레이어 중심 카메라 오프셋
- 데스크톱·모바일 뷰포트와 지도 경계 제한
- 진행 방향 가시 칸 수와 화면 밖 목표 화살표 계산

### `src/app.mjs`

- 게임 시작 시 안전 랜덤 시드 생성
- 신호와 이동체의 느린 틱 갱신
- 이동체 앞 대기·회피 텍스트와 기존 한영 음성 연결
- 모드 종료 시 카메라, 반복 입력과 틱 정리

## 오류 처리

- 랜덤 지도 검증이 20회 실패하면 고정 안전 배치로 대체한다.
- 이동체 틱이 지연되면 여러 칸을 건너뛰지 않고 최대 한 칸만 갱신한다.
- 이미지 또는 장식 애니메이션이 실패해도 장애물 판정과 텍스트 안내는 유지한다.
- 카메라 크기를 계산할 수 없으면 플레이어와 다음 목표가 함께 보이는 제한된
  전체 지도 화면을 사용한다.

## 테스트

### 모델

- 지도 너비가 14:4:14이고 세로 골목·보행길·횡단보도 폭이 정확한지 검사한다.
- 각 동네에 세로 골목 2개와 우회 가능한 보행 그래프가 있는지 검사한다.
- 두 횡단보도가 같은 신호를 따르고 차선과 올바른 방향으로 교차하는지 검사한다.
- 2~5를 만나기 전에 오른쪽 동네로 진입할 수 없는지 검사한다.
- 맨홀 옆 칸 회피와 공사 골목 전체 우회가 가능한지 검사한다.
- 이동체가 플레이어 칸에 진입하지 않고 정지·반전하는지 검사한다.
- 모든 난이도와 여러 랜덤 시드에서 2~10 친구와 학교까지 경로가 존재하는지
  검사한다.
- 랜덤 재시도 실패 시 고정 안전 배치가 선택되는지 검사한다.

### 카메라와 장면

- 지도 중앙에서 플레이어가 화면 중앙 셀에 유지되는지 검사한다.
- 네 방향 이동 뒤 진행 방향 가시 칸이 최소값을 만족하는지 검사한다.
- 지도 가장자리에서 카메라가 범위를 넘지 않는지 검사한다.
- 자동차·자전거·킥보드·맨홀·공사장에 색 외의 형태와 접근성 이름이 있는지
  검사한다.
- 감소된 움직임 설정에서 장식 애니메이션이 비활성화되는지 검사한다.

### 브라우저 회귀

- 1280×720, 390×844, 640×360에서 플레이어 중앙, 지도와 방향 버튼을 확인한다.
- 두 횡단보도의 방향과 14:4:14 공간 비율을 시각적으로 확인한다.
- 이동체가 왕복·정지·반전할 때 플레이어와 겹치지 않는지 확인한다.
- 기존 세기·더하기·빼기·곱하기와 길찾기 전체 테스트를 함께 실행한다.

- 실제 차량 교통 시뮬레이션
