# 모바일 숫자패드와 세기 캐릭터 개선 설계

## 목표

- 물리 키보드가 없는 모바일에서도 모든 게임의 답을 입력할 수 있게 한다.
- `몇 개일까요?`의 11~20 문제에서 지나치게 작은 노란 블록 묶음을 없애고, 기존 1~10과 같은 블록 친구 표현을 사용한다.
- 데스크톱 키보드 조작과 현재 음성·채점·난이도 규칙은 바꾸지 않는다.

## 모바일 숫자패드

- 게임 화면에 휴대폰형 3열 숫자패드를 추가한다.
- 배열은 `1 2 3 / 4 5 6 / 7 8 9 / 지우기 0`이다.
- 숫자 버튼은 기존 물리 숫자키와 동일한 입력 함수로 전달한다. 따라서 접두사가 정답과 일치하면 다음 자릿수를 기다리고, 답이 완성되면 기존 방식으로 채점한다.
- 지우기는 입력 버퍼의 마지막 숫자 하나를 제거하고 답 칸을 갱신한다.
- 패드는 모바일 너비 또는 터치 중심 환경의 게임 화면에서만 보인다. 홈 화면과 일반 데스크톱 화면에서는 숨긴다.
- 각 버튼은 최소 44px 터치 영역, 명확한 `aria-label`, 눌림 상태를 제공한다.

## 세기 문제 표현

- 1~20의 모든 세기 문제는 `character(number)`가 반환하는 기존 캐릭터 자산을 사용한다.
- 11~20에서 사용하던 작은 `quantity-visual`은 문제 본문에서 제거한다.
- 캐릭터에 별도의 정답 숫자 글자는 덧붙이지 않는다. 아이가 몸을 이루는 칸과 모양을 보고 답하도록 한다.
- 11~20 캐릭터도 1~10과 같은 무대 안전 영역 안에서 가능한 크게 표시한다.
- 정답 후 축하 화면과 10개 묶음 힌트 문구는 기존 동작을 유지한다.

## 반응형 배치

- 모바일 세로 화면에서는 문제 문구, 캐릭터 무대, 답 칸, 숫자패드 순으로 배치한다.
- 숫자패드가 추가되어도 캐릭터와 답 칸을 가리지 않도록 게임 무대 높이와 캐릭터 최대 높이를 줄여 전체를 한 화면에 맞춘다.
- 가로 화면과 데스크톱에서는 현재 무대 크기와 키보드 안내를 유지한다.
- 모바일에서는 물리 키보드 안내 대신 화면 숫자패드 안내를 사용한다.

## 구현 경계

- 기존 `applyDigit`와 정답 처리 흐름을 재사용한다.
- 지우기 동작은 입력 버퍼 변환 함수로 분리해 독립적으로 테스트한다.
- 숫자패드 마크업은 `index.html`, 표시와 반응형 배치는 `styles.css`, 클릭 연결은 `src/app.mjs`에 둔다.
- 캐릭터 자산과 음성 파일은 다시 생성하지 않는다.

## 검증

- 숫자패드 0~9와 지우기 버튼의 정적 계약을 검사한다.
- 화면 버튼 숫자 입력이 물리 키보드와 동일한 입력 함수로 연결되는지 검사한다.
- 지우기가 빈 버퍼와 여러 자리 버퍼에서 안전하게 동작하는지 단위 테스트한다.
- 11과 20의 세기 문제가 `quantity-visual`이 아니라 캐릭터 자산을 렌더링하는지 검사한다.
- 전체 자동 테스트를 실행한다.
- 390×844 모바일 화면에서 홈 선택, 게임 시작, 두 자리 답 입력, 지우기, 정답 완료와 요소 겹침 여부를 브라우저로 확인한다.

## 완료 기준

- 모바일에서 외부 키보드 없이 1~100 범위 답을 입력할 수 있다.
- 11~20 세기 문제의 캐릭터가 무대에서 명확하게 보인다.
- 숫자패드, 답 칸, 캐릭터가 모바일 화면에서 서로 겹치지 않는다.
- 기존 PC 키보드와 음성·게임 방식에 회귀가 없다.
