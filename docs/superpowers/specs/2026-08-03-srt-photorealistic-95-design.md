# 칙칙폭폭 기관사 — 실사형 SRT 시각 재구성 설계

## 1. 목표

사용자가 제공한 `SRT 운전 미니게임` 콘셉트 보드를 시각 기준으로 삼아 7번 게임을 다시 그린다.
목표는 기존 평면 SVG를 조금 더 세밀하게 만드는 것이 아니라, **실제 SRT를 촬영한 듯한 열차·선로·운전실과 기존 숫자블록 게임 UI를 결합한 2.5D 운전 게임**이다.

다음 항목을 모두 충족했을 때 “참고 이미지와 95% 이상 적합”으로 판정한다.

- SRT의 흰색 차체, 자주색 지붕과 허리선, 유선형 전두부, 창 띠, 대차, 연결부, 팬터그래프가 즉시 식별된다.
- 외부 주행 화면은 `열차·선로를 포함한 월드 70~72% + 조작부 28~30%`의 콘셉트 보드 구도를 따른다.
- 운전실은 전면 창, 실제 선로 원근, 어두운 계기판, 중앙 속도계, 좌측 가감속 레버가 한 화면에서 읽힌다.
- 평야·도심·교외·산악·해안·터널이 사진에 가까운 질감과 원근으로 구분된다.
- 숫자 친구, 별, 홈, 소리, 안내 문구는 기존 1~6번 게임의 친근한 2D 표현을 유지한다.
- 1280×720에서 핵심 열차와 조작 장치가 참고 보드와 같은 시각적 우선순위를 가진다.

게임 규칙, 역 순서, 입력, 별 판정, 탑승, 음성은 변경하지 않는다.

## 2. 선택한 구현 방식

### 채택: 실사형 WebP 레이어 + DOM/SVG 조작부

열차·운전실·환경은 고해상도 래스터 자산으로 만들고, 속도계·레버·신호·별·숫자 친구는 현재 DOM/SVG 상태와 연결한다.

이 방식이 적합한 이유:

- 순수 SVG보다 재질, 빛, 유리, 금속, 원경을 사실적으로 표현할 수 있다.
- WebGL 3D보다 현재 무의존 정적 사이트 구조와 테스트 계약을 덜 흔든다.
- 열차를 선명하게 두고 배경 레이어만 이동·블러 처리해 속도감을 안정적으로 만들 수 있다.
- 이미지 자산은 WebP로 압축하고 장면별로 지연 로드해 GitHub Pages에서도 실행 가능하다.

### 기각한 방식

1. **순수 SVG 고도화**: 현재 방식과 가장 안전하지만 콘셉트 보드의 광택, 재질, 운전실 깊이를 95% 수준으로 재현할 수 없다.
2. **WebGL/3D 모델**: 카메라 자유도는 높지만 모델·텍스처·렌더러 의존성과 모바일 GPU 비용이 크다. 이번 작업 범위를 넘어선다.

## 3. 시각 구조

### 외부 운전 화면

- 상단 8%: 별, 속도, 제한속도, 홈·소리만 배치한다.
- 상단 71% 월드: 사진형 배경과 SRT 측면/3분의 2 전면 열차를 배치한다.
- 하단 29% 콘솔: 실제 운전대에서 가져온 어두운 패널 위에 레버, 대형 원형 속도계, 경적과 문 상태를 둔다.
- 열차는 중앙 세로 영역의 최소 22% 높이를 차지하고, 노즈와 후미가 잘리지 않는다.
- 배경은 하늘, 먼 도시/산, 선로변, 레일의 네 레이어로 분리한다. 속도가 높을수록 가까운 레이어만 더 빠르고 흐리게 움직인다.

### 운전실 화면

- 전면 창이 화면 너비의 70% 이상을 차지한다.
- 선로 소실점은 화면 가로 중앙, 세로 38~42%에 둔다.
- 계기판은 실제처럼 보이되 조작 가능한 요소는 세 개만 강조한다: 가감속 레버, 속도계, 경적.
- 나머지 버튼과 화면은 장식으로 두고 대비를 낮춰 어린이가 조작 대상을 혼동하지 않게 한다.
- 다음 역과 제한속도는 운전창 위에 작은 실제형 표지로 표시한다.

### 환경

각 환경은 16:9 고해상도 배경 한 장과 이동 가능한 전경 레이어를 가진다.

| 환경 | 핵심 표현 |
|---|---|
| 평야 | 맑은 하늘, 넓은 논밭, 멀리 이어지는 전차선 |
| 도심 | 고층 건물, 방음벽, 교량, 밀도 높은 전차선 |
| 교외 | 낮은 주택, 나무, 완만한 구릉 |
| 산악 | 터널 입구, 절개지, 짙은 산림 |
| 해안 | 바다 반사광, 해안선, 낮은 아침 햇빛 |
| 터널 | 콘크리트 벽, 일정 간격 조명, 전조등 반사 |

## 4. 자산 계약

신규 자산은 `assets/train-realistic/` 아래에 둔다. Task 6에서 실제 매니페스트와 파일을
대조한 최종 자산 계약은 다음 아홉 장이다.

- `srt-exterior-{city,field,river,mountain,sea,tunnel}.webp`: 환경과 열차를 함께 잠근 외부 장면 6장
- `cab-{day,night,tunnel}.webp`: 동일한 계기판 구도를 유지한 운전실 베이스 3장

초기안의 투명 열차·별도 전경 합성 대신 전체 프레임 외부 장면을 채택했다. 이렇게 해야 환경을
바꿔도 열차 실루엣, 도색, 카메라 높이와 조명 방향이 흔들리지 않는다. `river` 이미지는 원안의
교외 기준을 없애거나 대체하는 예외가 아니라, 낮은 구릉·수목대·아파트 원경과 강을 함께 담은
**교외/도시간 강변 구간**의 시각 자산이다. 따라서 6종 판정에서도 `river`를 교외 환경 기준으로
그대로 평가한다. 선택·결과 화면과 이미지 실패 상태는 별도 래스터 없이 기존 캐노니컬 SVG를 사용한다.

자산 생성 규칙:

- 워터마크, 사진 저작권 표식, 불필요한 텍스트를 넣지 않는다.
- SRT 로고는 현재 게임이 사용 중인 글자 표기 수준으로만 유지한다.
- 열차 방향과 조명 방향을 모든 장면에서 통일한다.
- 2× 해상도로 생성하고 실제 표시 크기에서는 축소해 선명도를 확보한다.
- 단일 이미지에 UI 글자나 속도 숫자를 구워 넣지 않는다. 상태 정보는 코드가 표시한다.

## 5. 코드 경계

- `ktx-journey.mjs`: 변경하지 않는다. 주행 상태와 규칙의 단일 원본이다.
- `ktx-scene-art.mjs`: 래스터 자산을 선택하는 순수 함수와 접근성 대체 텍스트를 제공한다.
- `ktx-scene.mjs`: 상태에 따라 배경, 운전실, 열차 레이어의 클래스와 CSS 변수를 갱신한다.
- `styles.css`: 실사 장면 레이아웃, 패럴랙스, 조명, 모션 블러를 담당한다.
- `mobile-games.css`: 844×390 가로 모바일 전용 계기판 재배치와 터치 영역을 담당한다.
- 기존 캐노니컬 SVG는 저사양·이미지 로드 실패·줄인 동작 환경의 폴백으로 남긴다.

## 6. 성능과 접근성

- 첫 장면에 필요한 자산만 즉시 로드하고 나머지는 다음 구간 직전에 미리 불러온다.
- 개별 WebP는 권장 350KB 이하, 전체 신규 자산은 권장 6MB 이하로 맞춘다.
- 이미지가 실패하면 기존 SVG 장면으로 자동 복귀한다.
- `prefers-reduced-motion`에서는 배경 이동과 진동을 줄이되 속도·정차 판정은 그대로 유지한다.
- 조작 버튼은 모바일에서 최소 48×48px을 확보한다.
- 배경 이미지에는 의미를 맡기지 않는다. 역, 속도, 정차 신호는 텍스트와 도형으로도 전달한다.

## 7. 테스트와 시각 판정

### 자동 테스트

1. 신규 자산 매니페스트가 모든 환경·열차 뷰를 제공한다.
2. 상태별 올바른 자산이 선택된다.
3. 이미지 실패 시 캐노니컬 SVG 폴백이 유지된다.
4. 기존 408개 테스트가 모두 통과한다.
5. 기존 “사진 텍스처 금지” 테스트는 7번 게임의 승인된 `assets/train-realistic/`만 허용하도록 좁힌다.

### 브라우저 검증

- 1280×720: 선택, 출발, 83km/h, 209km/h, 정차, 운전실 주간, 야간, 터널, 결과 화면.
- 844×390: 외부, 운전실, 열차 선택, 결과 화면.
- 콘솔 오류 0, 가로 스크롤 0, 핵심 버튼 잘림 0.

### 95% 적합 판정표

| 항목 | 가중치 |
|---|---:|
| SRT 실루엣·도색·세부 | 25 |
| 외부 게임 화면 구도 | 20 |
| 운전실 사실감 | 20 |
| 환경 6종 사실감 | 15 |
| 계기판·레버·속도계 위계 | 10 |
| 기존 숫자블록 UI 결합 | 5 |
| 모바일 가로 재배치 | 5 |

각 항목을 참고 이미지와 나란히 확인한다. 총점 95점 미만이면 완료로 보고하지 않는다.
