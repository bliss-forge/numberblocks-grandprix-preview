# 큰 숫자 캐릭터 C2 확대 설계

## 목표

- 11~150 캐릭터가 1~10 캐릭터보다 확실히 크게 느껴지게 한다.
- 문제 화면에서는 숫자 크기 차이를 보여 주고, 정답 화면에서는 더 강한 보상 연출을 제공한다.
- 캐릭터가 커져도 화면 아래쪽의 숫자·수식 영역을 침범하지 않는다.
- 1~10의 현재 크기, 캐릭터 자산, 음성, 문제 생성과 정답 판정은 변경하지 않는다.

## 승인된 방향

선택한 방향은 C2 `매우 강하게`다.

1. 문제 화면에서 큰 수 캐릭터를 현재보다 더 크게 표시한다.
2. 정답을 맞히면 같은 캐릭터를 한 단계 더 크게 확대한다.
3. 확대는 숫자만 보고 일괄 적용하지 않고 캐릭터의 기존 숫자 구간 배율과 형태 보정을 함께 사용한다.
4. 캐릭터 구역과 수식 구역을 물리적으로 분리한다. 공간이 부족하면 캐릭터를 줄이고 수식 구역은 항상 보존한다.

## 크기 기준

### 문제 화면

보이는 몸체 면적은 1~10 캐릭터의 기준 면적보다 최소한 다음 비율만큼 크게 보이게 한다.

| 숫자 범위 | 문제 화면 최소 몸체 면적 |
|---|---:|
| 1~10 | 현재 크기 1.0배 |
| 11~20 | 1.5배 |
| 21~50 | 1.7배 |
| 51~100 | 1.9배 |
| 101~150 | 2.1배 |

기존 `--number-scale`, `--shape-scale`, `--shape-width-scale` 계산 결과가 이 기준보다 크면 기존 결과를 유지한다. 좁고 긴 캐릭터는 현재 가로 면적 보정을 계속 사용한다.

### 정답 화면

- 11~150 정답 캐릭터에는 문제 화면보다 강한 정답 전용 확대를 추가한다.
- 정답 캐릭터의 목표 몸체 면적은 같은 숫자의 문제 화면 면적보다 정확히 1.4배 크게 한다.
- 정답 캐릭터는 캐릭터 구역의 사용 가능한 크기 안에서만 확대한다.
- 완성된 식은 별도의 고정 행에 유지한다.

## 수식 보호 구역

현재 `.operand-scene`과 `.celebration-result`는 이미 `minmax(0, 1fr) auto` 두 행 구조를 사용한다. 이 구조를 명시적인 캐릭터 행과 수식 행으로 강화한다.

- 위쪽 행은 캐릭터 전용 구역이다.
- 아래쪽 행은 `.equation-label` 또는 `.completed-equation` 전용 구역이다.
- 캐릭터 전용 구역은 가로 88%, 세로 82%를 안전 영역으로 사용한다.
- 캐릭터 확대는 안전 영역 안에서만 허용한다.
- 캐릭터 전용 구역은 수식 행 방향의 넘침을 차단한다.
- 수식 행은 캐릭터 확대와 애니메이션의 영향을 받지 않는다.
- 연산 기호는 캐릭터 행 안에 유지하며 두 캐릭터와 겹치지 않는다.

캐릭터가 목표 배율에 도달할 공간이 없으면 목표 배율보다 작게 표시한다. 수식을 가리거나 화면 밖으로 내보내는 것보다 전체 노출을 우선한다.

## 화면별 동작

### 일반 데스크톱

- 문제 화면에서는 숫자 구간별 최소 면적 기준을 적용한다.
- 정답 화면에서는 문제 화면보다 정확히 1.4배 큰 몸체 면적을 목표로 한다.
- 11~150은 크기 구간이 올라갈수록 더 크게 보인다.

### 모바일 세로

- 동일한 크기 구간과 형태 보정을 사용한다.
- 숫자판과 답 칸을 먼저 확보한 뒤 남은 무대 높이 안에서 캐릭터를 확대한다.
- 수식 행의 높이는 줄일 수 있지만 캐릭터 행과 겹치게 하지 않는다.

### 낮은 가로 화면

- 기존 구간별 화면 상한 `1.0`, `1.1`, `1.15`, `1.2`, `1.25`를 유지한다.
- 추가 가로 확대는 계속 `1`로 제한한다.
- C2 목표 면적보다 전체 캐릭터, 연산 기호, 수식, 답 칸과 숫자판의 노출을 우선한다.

## 적용 범위

- 더하기, 빼기, 곱하기 문제의 피연산자 캐릭터
- 정답을 맞힌 뒤 표시되는 11~150 정답 캐릭터

다음 화면은 이번 변경에서 제외한다.

- 홈 화면의 1~5 모드 카드 캐릭터
- 10과 낱개 친구로 분해해 보여 주는 숫자 세기 화면
- 결과가 150을 넘을 때 사용하는 결과 팻말

## 구성 요소

### 보이는 몸체 메타데이터

`scripts/png_alpha_bounds.mjs`가 이미 계산하는 불투명 픽셀 수를 사용해 각 자산의 정규화된 몸체 면적을 만든다.

```text
정규화 몸체 면적 = 불투명 픽셀 수 / (PNG 너비 × PNG 높이)
```

생성 스크립트는 1~150의 정규화 몸체 면적을 브라우저에서 읽을 수 있는 정적 모듈로 출력한다. 사람이 숫자별 배율표를 관리하지 않는다. 캐릭터 자산이 다시 생성되면 몸체 메타데이터도 같은 명령에서 다시 생성한다. 테스트는 PNG에서 다시 계산한 값과 정적 모듈의 값이 일치하는지 검사해 오래된 메타데이터가 남지 않게 한다.

### 장면별 확대 계산

`src/app-behavior.mjs`에 숫자, 장면 종류, 정규화 몸체 면적을 받아 장면별 확대값을 반환하는 순수 계산을 둔다. 이 계산은 기존 숫자 구간과 형태 보정을 대체하지 않고 장면별 목표를 추가한다.

장면은 다음 두 종류만 사용한다.

- `problem`: 문제 화면
- `celebration`: 정답 화면

1~10 중 가장 큰 정규화 몸체 면적을 기준 면적으로 사용한다. 기존 숫자·형태·가로 배율을 적용한 예상 몸체 면적이 목표보다 작을 때만 다음 추가 균일 배율을 사용한다.

```text
추가 배율 = sqrt(목표 몸체 면적 / 기존 예상 몸체 면적)
```

기존 예상 면적이 이미 목표를 넘으면 추가 배율은 `1`이다. 따라서 현재 잘 보이는 넓은 캐릭터를 불필요하게 더 키우지 않고, 19처럼 좁은 캐릭터만 목표에 도달할 만큼 추가 확대한다.

잘못된 숫자나 장면 값이 들어오면 추가 확대 `1`을 반환한다.

### 공유 캐릭터 경로

`src/app.mjs`의 공통 `character()`가 기존 형태 변수와 함께 장면별 확대에 필요한 데이터 속성 또는 CSS 변수를 설정한다. 장면을 만드는 쪽은 `problem` 또는 `celebration`만 전달한다.

### 레이아웃 경계

`styles.css`에서 문제와 정답 장면의 캐릭터 행에 안전 영역과 넘침 차단을 적용한다. 수식 행은 독립적으로 크기를 확보한다. 낮은 화면용 상한은 기존 미디어 쿼리에서 최종 우선권을 가진다.

## 애니메이션

- 기존 입장, 정답, 오답 애니메이션은 유지한다.
- 확대 배율은 CSS `scale` 속성을 사용하고 애니메이션의 `transform`과 분리한다.
- 정답 애니메이션 중에도 캐릭터의 보이는 몸체가 수식 구역으로 내려오지 않게 한다.
- `prefers-reduced-motion` 동작은 변경하지 않는다.

## 오류와 안전 동작

- 캐릭터 자산을 불러오지 못하면 현재 숫자 대체 표시를 유지한다.
- 계산값이 유한하지 않으면 추가 확대 `1`을 사용한다.
- 화면 공간이 목표 크기보다 작으면 안전 상한을 적용한다.
- 확대 실패가 문제 생성, 입력, 음성 또는 다음 문제 진행을 막지 않는다.

## 검증

### 자동 테스트

- 1~10의 장면별 추가 확대가 항상 `1`인지 검사한다.
- 각 숫자 구간의 문제 화면 면적 목표가 `1.5`, `1.7`, `1.9`, `2.1`인지 검사한다.
- 정답 화면 목표가 같은 숫자의 문제 화면보다 정확히 1.4배 큰 면적인지 검사한다.
- 잘못된 숫자와 장면 값이 안전값 `1`을 반환하는지 검사한다.
- 1~150의 정적 몸체 메타데이터가 실제 PNG 불투명 면적과 일치하는지 검사한다.
- 11~150 전체의 목표 배율 적용 전 예상 몸체 면적이 숫자 구간별 최소값에 도달하는지 검사한다.
- 대표적인 좁은 캐릭터 19, 넓은 캐릭터 50, 큰 캐릭터 100과 150을 별도 회귀 사례로 유지한다.
- 문제 장면과 정답 장면이 캐릭터 행과 수식 행을 분리하고 낮은 가로 화면 상한을 유지하는지 CSS 계약 테스트한다.
- 기존 전체 테스트를 실행해 음성, 입력, 난이도와 문제 생성 회귀가 없는지 확인한다.

### 브라우저 검증

다음 화면에서 캐릭터의 보이는 실루엣과 수식 영역의 경계가 겹치지 않는지 확인한다.

- 1280×720: `19 − 3`, 큰 수 피연산자, 100과 150 정답 화면
- 390×844: 모바일 숫자판을 포함한 `19 − 3`과 큰 수 정답 화면
- 640×360: 낮은 가로 화면의 기존 안전 상한

검증 조건은 다음과 같다.

- 캐릭터 행의 아래 경계가 수식 행의 위 경계를 넘지 않는다.
- 연산 기호와 두 캐릭터가 서로 가리지 않는다.
- 수식, 답 칸과 모바일 숫자판이 항상 조작 가능하다.
- 캐릭터의 팔다리와 장식이 안전 영역 안에서 보인다.
- 브라우저 콘솔 오류가 없다.

## 완료 기준

- 11~150 캐릭터가 문제 화면에서 1~10보다 확실히 크게 보인다.
- 정답 화면에서 큰 수 캐릭터가 문제 화면보다 한 단계 더 크게 보인다.
- 캐릭터가 `19 − 3` 같은 수식 영역을 침범하지 않는다.
- 1~10의 현재 크기와 모든 게임 동작은 바뀌지 않는다.
- 데스크톱, 모바일 세로, 낮은 가로 화면에서 캐릭터와 조작 영역이 잘리지 않는다.
