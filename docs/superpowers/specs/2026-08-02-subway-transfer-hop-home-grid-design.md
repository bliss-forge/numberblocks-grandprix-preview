# 지하철 환승 하차 놀이와 1~10 홈 그리드 설계

## 목표

6번 지하철 여행에서 환승역에 내릴 때도 발빠짐 타이밍 놀이를 통과하게 한다. 환승 하차 중에는 도착 멜로디나 축하 음악을 재생하지 않는다. 동시에 홈 화면을 앞으로 10개 놀이를 수용할 수 있는 짧은 카드형 5×2 구조로 바꾸고, 서로 충돌하는 숫자키 단축키를 제거한다.

## 범위

- 목적지와 환승역이 같은 하차 타이밍 판정과 화면을 사용한다.
- 최종 목적지는 기존 도착 멜로디를 유지한다.
- 환승역은 음악 없이 문 열림 효과와 발빠짐 안내 뒤 즉시 타이밍 놀이를 시작한다.
- 환승 타이밍 성공 뒤에만 환승 통로가 열린다.
- 홈 카드 1~7을 짧게 만들고 PC에서 5열로 배치한다.
- 게임·난이도의 숫자키 단축키와 숫자키 안내를 제거한다.
- 게임 8~10 자체는 이번 범위에 포함하지 않는다.

## 지하철 상태 설계

기존 `arriving` 상태를 목적지와 환승이 함께 쓰도록 확장한다.

```text
ride
 ├─ 목적지 하차 → arriving(destination, melody)
 │                  → arriving(destination, hop)
 │                  → arrived
 └─ 환승역 하차 → arriving(transfer, hop)
                    → corridor
```

`arriving`에는 다음 의미가 들어간다.

- `kind`: `destination` 또는 `transfer`
- `stage`: `melody` 또는 `hop`
- `phaseMs`: 타이밍 표시의 현재 시간
- `misses`: 실패 횟수
- `offPlan`: 계획에 없던 환승역 하차 여부. 환승일 때만 사용한다.

목적지 하차는 지금처럼 `melody`에서 시작해 기존 시간 뒤 `hop`으로 넘어간다. 유효한 환승역 하차는 `hop`에서 바로 시작한다. 잘못된 일반 역은 기존처럼 `not-your-stop`을 반환해 하차 화면을 열지 않는다.

타이밍 성공 시 `kind`에 따라 다음 상태를 결정한다.

- `destination`: `arrived`로 이동하고 기존 사진 놀이 또는 완료 흐름을 계속한다.
- `transfer`: 기존 환승 통로 방을 만들어 `corridor`로 이동한다. 성공 전에는 통로 상태를 만들지 않는다.

기존 접근성 보조와 난이도 완화는 유지한다. `prefers-reduced-motion`에서는 항상 성공하고, 일반 모드도 세 번 실패한 뒤 네 번째 입력은 반드시 성공한다. 실패는 별이나 점수를 깎지 않는다.

## 환승 하차 화면과 음성

목적지와 환승은 열차 내부, 열린 문, 발빠짐 틈, 노란 안전 구간, 왕복하는 빨간 표시, 플레이어 캐릭터를 공유한다.

환승 화면은 다음 차이를 가진다.

- 역명 표시는 `종합운동장역 · 환승`처럼 환승 상황을 명시한다.
- 안내 문구는 `빨간 표시가 노란 칸에 올 때 ⎵!`로 짧게 유지한다.
- 멜로디 대기 단계 없이 문과 타이밍 표시가 즉시 활성화된다.
- 도착 멜로디, 축하 음악, 도착 승리 효과는 재생하지 않는다.
- 문 열림 효과음과 `발빠짐 주의` 안내는 한 번만 재생한다.
- 성공하면 짧은 키/성공 효과 뒤 환승 통로로 전환한다.
- 환승 통로가 열린 뒤 기존 환승 안내를 재생한다.

PC는 스페이스, 모바일은 기존 큰 `⎵` 버튼을 사용한다. 방향키를 누르면 판정하지 않고 스페이스 안내를 유지한다.

## 홈 화면 구조

### PC

- `.mode-grid`를 최대 5열로 고정한다.
- 현재 1~7은 첫째 줄 1~5, 둘째 줄 6~7 순서로 놓인다.
- 8~10이 추가되면 둘째 줄의 남은 칸을 그대로 채운다.
- 카드 최소 높이는 현재보다 약 25% 줄이고, 캐릭터 영역 약 58%, 문구 영역 약 42% 비율을 사용한다.
- 캐릭터 이미지는 `object-fit: contain`으로 온전히 보이게 한다.
- 1366×768 이상에서는 홈이 한 화면에 들어오도록 제목, 난이도, 카드 간격을 함께 압축한다.

### 모바일

- 2열 그리드를 유지한다.
- 카드 수가 홀수일 때 마지막 카드만 전체 너비를 사용한다.
- 현재 5번만 전체 너비를 쓰는 특별 규칙은 제거한다.
- 8~10이 추가되어 짝수가 되면 모든 카드가 균일한 2열이 된다.
- 세로 스크롤은 허용하고 가로 넘침은 허용하지 않는다.

## 선택 입력 정리

- 홈의 `1 2 3 4 5 6 중 하나를 눌러 시작해요!` 줄을 삭제한다.
- 카드의 `aria-keyshortcuts`를 삭제한다.
- 난이도 버튼 안의 `7`, `8`, `9` 키캡과 `aria-keyshortcuts`를 삭제한다.
- 홈에서 숫자키로 게임이나 난이도를 고르는 전역 키 처리도 삭제한다.
- 카드와 난이도 버튼은 클릭·터치, 포커스 후 Enter/Space로 선택한다.
- 수학 문제의 숫자 입력과 지하철 내부 호선·목적지 숫자 선택은 이번 변경 대상이 아니다.
- `키보드로 만나는` 문구는 입력 방식과 무관한 놀이터 문구로 바꾼다.
- 홈 아래 숫자키 사용 안내도 삭제한다.

## 오류 처리와 접근성

- 타이밍 입력이 너무 빠르면 실패 횟수를 늘리지 않는 기존 유예 시간을 유지한다.
- 실패 시 화면과 안내만 갱신하고 상태는 `arriving`에 머문다.
- 환승 통로 생성에 필요한 역·방 정보는 기존 `buildRoom("corridor")` 경로를 재사용한다.
- 타이밍 미터와 틈의 `aria-label`을 유지하고 환승 여부를 안내 문구에 포함한다.
- 홈 카드의 번호 배지는 순서 표식으로 유지하되 키보드 단축키로 설명하지 않는다.
- 애니메이션 감소 환경에서는 움직이는 표시를 안전 구간에 고정하고 판정도 즉시 성공시킨다.

## 테스트

### 모델

- 환승역에서 내리면 바로 통로가 아니라 `arriving(kind=transfer, stage=hop)`이 된다.
- 환승 타이밍 성공 뒤에만 `corridor`가 생성된다.
- 환승 실패, 네 번째 자동 성공, 보조 모드 성공을 검증한다.
- 목적지는 계속 `melody → hop → arrived` 순서를 따른다.
- 일반 역 오답 하차는 계속 차단된다.

### 장면과 앱

- 환승 하차 화면은 환승 역명, 열린 문, 활성 미터를 렌더링한다.
- 환승 진입 이벤트가 도착 멜로디를 호출하지 않는지 검증한다.
- 목적지 진입 이벤트는 기존 멜로디 호출을 유지한다.
- 환승 성공 뒤 기존 환승 통로 안내가 시작되는지 검증한다.

### 홈

- 카드와 난이도 버튼에 숫자 단축키 속성·키캡이 없는지 검증한다.
- 전역 홈 숫자키 선택 코드가 제거되었는지 검증한다.
- PC 1366×768과 1920×1080에서 5열과 줄어든 카드 높이를 브라우저로 검증한다.
- 모바일 360×640, 390×844, 430×932에서 2열, 마지막 홀수 카드 전체 너비, 가로 넘침 없음을 검증한다.

## 비목표

- 게임 8~10 구현
- 수학 문제 숫자 입력 방식 변경
- 지하철 목적지 선택과 호선 선택의 게임 내부 숫자키 제거
- 기존 목적지 사진 놀이 및 가족 도착 피날레 변경
- 새로운 음원 제작
