# 연결형 숫자 캐릭터와 두 친구 문제 화면 설계

## 배경

현재 `number-001.png`부터 `number-100.png`까지의 새 캐릭터 팩은 숫자별 블록 수는 맞지만, 큰 수가 지나치게 길거나 작게 표시되고 1~10 기존 캐릭터와 그림체가 달라 보인다. 더하기 문제에서도 큰 피연산자를 숫자와 점 묶음 카드로 표시해 사용자가 기대한 “블록 친구끼리 만나는” 장면이 되지 않는다.

이번 변경은 1~10 기존 캐릭터의 친근한 인상을 기준으로 삼고, 11~100을 제공된 참고 작품의 실루엣과 색 구성을 참고한 연결형 블록 친구로 다시 제작한다. 더하기와 곱셈 문제에는 두 피연산자 캐릭터를 함께 보여주고 그 아래에 식을 표시한다.

## 목표

- 1~10은 기존 `one.png`부터 `ten.png`까지의 캐릭터를 그대로 사용한다.
- 11~100은 모든 칸이 빈틈없이 붙은 하나의 몸체로 다시 만든다.
- 11~100의 실루엣, 색 띠, 장식, 얼굴 위치는 사용자가 지정한 1~100 참고 작품을 숫자별 디자인 자료로 사용한다.
- 모든 캐릭터가 게임 화면에서 비슷한 시각적 존재감을 갖도록 표시 크기를 정규화한다.
- 더하기와 곱셈 문제에서 두 피연산자를 모두 블록 친구로 보여준다.
- 피연산자 아래에 `6 + 38`, `6 × 8` 같은 식을 항상 명확히 표시한다.
- 현재 음성, 난이도, 문제 생성, 정답 판정, 키보드 입력 방식은 유지한다.

## 비목표

- 외부 참고 작품을 그대로 잘라 쓰거나 원본 이미지를 게임 자산으로 포함하지 않는다.
- 1~10 캐릭터를 새 스타일로 다시 그리지 않는다.
- 새로운 게임 모드나 난이도를 추가하지 않는다.
- 음성 또는 효과음을 교체하지 않는다.
- 캐릭터에 새로운 3D 조명이나 과도한 입체 효과를 추가하지 않는다.

## 캐릭터 디자인 규칙

### 1~10

런타임 자산 선택은 다음 기존 파일을 사용한다.

- `one.png`
- `two.png`
- `three.png`
- `four.png`
- `five.png`
- `six.png`
- `seven.png`
- `eight.png`
- `nine.png`
- `ten.png`

기존 색, 표정, 팔다리, 블록 모서리 표현을 수정하지 않는다.

### 11~100

각 숫자는 독립된 투명 PNG 캐릭터로 제공한다. 캐릭터는 다음 규칙을 따른다.

1. 숫자값과 같은 개수의 셀을 사용한다.
2. 인접 셀 사이에는 공간을 두지 않는다.
3. 셀 경계선은 보이지만 몸체는 하나의 연결된 실루엣으로 읽혀야 한다.
4. 참고 작품의 숫자별 전체 모양, 주요 색, 띠, 왕관, 안경 같은 식별 요소를 반영한다.
5. 얼굴은 작은 셀 하나에 갇히지 않도록 여러 셀 위에 겹쳐 충분히 크게 그린다.
6. 팔과 다리는 몸체 바깥으로 자연스럽게 이어지며, 화면 경계를 벗어나지 않는다.
7. 그라디언트와 그림자는 1~10과 충돌하지 않는 최소한의 수준만 허용하고, 새 3D 스타일을 만들지 않는다.

38은 승인 시안의 기준 캐릭터다.

- 첫 줄은 가운데 3칸이다.
- 그 아래 7줄은 5칸 너비로 연결되어 총 38칸을 만든다.
- 위쪽 두 줄은 분홍 계열이다.
- 몸통은 연한 노랑 계열이며 중앙에 가는 분홍 띠가 있다.
- 얼굴은 몸통 아래쪽 중앙에 배치한다.
- 모든 칸은 틈 없이 붙는다.

다른 11~100 캐릭터도 같은 원리로 숫자별 참고 실루엣을 연결형 몸체로 해석한다.

## 크기 정규화

모든 PNG는 동일한 투명 캔버스 규격을 유지한다. 렌더러는 캐릭터의 실제 보이는 경계를 계산해 다음 기준에 맞춘다.

- 캐릭터의 긴 축이 공통 안전 영역의 82~88%를 차지한다.
- 팔다리를 포함한 전체 경계가 안전 영역 안에 들어간다.
- 정사각형, 세로형, 가로형의 고유 비율은 유지한다.
- 지나치게 긴 한 줄 배치는 피하고 참고 작품의 직사각형, 계단, 십 묶음, 색 띠 구성을 사용한다.
- 얼굴의 눈과 입은 일반적인 문제 화면에서 1~10 얼굴과 비슷한 크기로 읽혀야 한다.

즉, 큰 수가 작은 수보다 실제 블록 수만큼 거대해지지는 않지만 각 캐릭터의 고유한 비율과 셀 수는 유지한다.

## 문제 화면

### 더하기

기존의 `캐릭터 + 숫자 카드` 구성을 다음처럼 바꾼다.

1. 왼쪽에 첫 번째 피연산자 캐릭터
2. 가운데에 `+`
3. 오른쪽에 두 번째 피연산자 캐릭터
4. 두 캐릭터 아래에 전체 식

예: 6과 38 캐릭터 아래에 `6 + 38`

### 곱셈

더하기와 같은 구조를 사용한다.

1. 왼쪽에 첫 번째 피연산자 캐릭터
2. 가운데에 `×`
3. 오른쪽에 두 번째 피연산자 캐릭터
4. 두 캐릭터 아래에 전체 식

예: 6과 8 캐릭터 아래에 `6 × 8`

두 피연산자 슬롯은 같은 크기다. 각 캐릭터는 자신의 슬롯 안에서 `object-fit: contain` 방식으로 표시되며, 자산 자체의 보이는 경계 정규화와 함께 화면 점유 크기 차이를 줄인다.

### 숫자 세기와 정답 축하

숫자 세기 문제의 기존 점 묶음과 힌트는 유지한다. 정답을 맞춘 뒤에는 모든 모드에서 정답 숫자의 블록 친구를 보여주는 현재 흐름을 유지하되, 1~10은 기존 자산, 11~100은 새 연결형 자산을 사용한다.

## 자산 선택

숫자를 캐릭터 경로로 바꾸는 단일 함수를 사용한다.

- 1~10: 기존 이름 기반 자산
- 11~100: `number-011.png`부터 `number-100.png`

홈 화면, 문제 피연산자, 정답 축하 화면이 같은 선택 함수를 사용해 서로 다른 스타일의 파일을 선택하는 문제를 방지한다.

## 오류 처리

- 피연산자 캐릭터 이미지가 로드되지 않으면 해당 자리에 기존 숫자 카드를 한 번만 표시한다.
- 정답 캐릭터 이미지가 로드되지 않으면 현재 숫자 결과 보드로 대체한다.
- 이미지 오류가 문제 진행, 입력, 음성 재생을 중단시키지 않는다.

## 검증

자동 검증은 다음을 확인한다.

- 1~10이 기존 이름 기반 자산으로 매핑된다.
- 11~100이 새 숫자 기반 자산으로 매핑된다.
- 11~100의 셀 수가 숫자값과 정확히 일치한다.
- 모든 셀이 하나의 연결 성분을 이룬다.
- 인접 셀 사이에 시각적 간격을 만드는 렌더러 설정이 없다.
- 38이 승인된 `3 + 7×5` 구조와 색 영역을 사용한다.
- 더하기와 곱셈 문제에 두 개의 캐릭터 이미지와 하나의 식 라벨이 존재한다.
- 숫자 세기, 난이도, 오디오, 키보드 입력의 기존 테스트가 계속 통과한다.
- 11, 20, 38, 50, 72, 99, 100을 포함한 대표 캐릭터를 브라우저에서 비교해 크기, 얼굴 가독성, 잘림 여부를 확인한다.
- 1280×720과 좁은 화면에서 두 캐릭터와 식이 겹치지 않는지 확인한다.

## 완료 기준

- 사용자가 승인한 38처럼 11~100이 연결된 한 몸체로 보인다.
- 1~10의 기존 모습이 유지된다.
- 큰 수 캐릭터가 작거나 길게 찌그러져 보이지 않는다.
- 더하기와 곱셈에서 양쪽 수가 모두 블록 친구로 표시된다.
- 식이 캐릭터 아래에서 항상 읽힌다.
- 기존 게임과 음성 동작에 회귀가 없다.
