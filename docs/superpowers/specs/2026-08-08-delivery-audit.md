## B. 설계 최소 개정 (감사 결과 반영, 6건)

각 개정은 스펙의 해당 절만 바꾸고 마일스톤 순서는 유지한다.

### B-1. "8번째 게임" → **9번째 게임** (스펙 전반·§12·§17)
저장소에 카드가 이미 8장 있다. 택배는 **9번 카드**이며 캐릭터 계약상 `assets/characters/nine.png`를 쓴다.
→ **스펙 §12-1의 "카드 비주얼: 코드 SVG 노란 트럭"은 CLAUDE.md 카드 계약과 충돌한다.** 카드 이미지는 `nine.png`(넘버블록 9)로 하고, **노란 트럭 SVG는 카드 안이 아니라 게임 안(주행 씬·시작 오버레이)의 주인공**으로 쓴다. 신규 이미지 자산 0장 원칙은 유지된다(`nine.png`는 기존 자산).

### B-2. 홈 키 문제는 **이미 해결됨** (스펙 §12 전체)
저장소에 숫자키 숏컷이 애초에 없다. 따라서 §12의 "8번째 카드 키 문제", "0 배정 협상", "무숏컷 항구 원칙 선언"은 **모두 무의미하거나 이미 충족**이다.
→ §12는 다음 한 줄로 대체한다: **"카드 1장을 그리드 끝에 가산한다. 기존 카드의 위치·`data-mode`·이미지·문구를 바꾸지 않는다. 진입은 ←/→ + Space(저장소 표준)."** 회귀 테스트는 기존 `app-contract.test.mjs`의 카드 계약 확장으로 충분하다(FN-17/TF-B1 논의는 대상 자체가 없어 종결).

### B-3. 이탈 키: **0 홀드 2초 → `Escape`** (스펙 §2, §2-3)
저장소 전 게임의 이탈은 `Escape`이고 화면에도 "처음" 버튼이 상주한다. 스펙 §2-1이 이미 "기존 컨벤션이 확인되면 그것을 따른다"고 위임했다.
→ **0 홀드 이탈·홀드 링·450ms 유예·그림 2택 전부 삭제.** 이탈 = `Escape` + `#home-btn` 클릭. 이 개정으로 스펙 §2-3의 "0키 충돌" 문제는 **원인 자체가 사라진다**(0은 어디에도 배정되지 않음). 층 1~9만 쓰는 규칙은 그대로 유지(0층·지하 없음).
→ 부수 효과: 체크포인트 "이어서/처음부터" 2택도 삭제 대상이 아니라 **유지**하되(§1-2), 진입 오버레이의 그림 2택은 ←/→ + Space로 고른다(홈 카드와 같은 조작).

### B-4. 테스트 기준선 **439**, 디렉터리 `tests/`, 씬 테스트는 FakeElement 허용 (스펙 §15)
- 기준선 439(감사 ⑪). 완료 기준의 "기존 전부 통과"는 439를 분모로 한다.
- 파일 경로는 `tests/delivery-*.test.mjs`.
- 스펙의 "DOM 미테스트" 제약을 **저장소 관행에 맞춰 완화**: 씬 렌더러는 FakeElement 가짜 DOM으로 계약 테스트를 쓴다(실제 DOM·브라우저는 여전히 테스트 대상 아님). 이는 스펙 §2-8의 "node --test만" 불변식과 충돌하지 않는다.

### B-5. 렌더 아키텍처: rAF 루프 → **틱 스케줄러 + 재렌더 문법** (스펙 §2-9, §5-7, §14)
저장소에 rAF 게임 루프도 노드 풀도 없다. 새 게임만 다른 아키텍처를 쓰면 유지보수가 갈린다.
→ 시뮬은 스펙대로 **고정 스텝 1/60 순수 모듈**(`delivery-sim.mjs`)로 두되, **구동은 기존 `schedule*Tick` 패턴**을 따르고 화면 갱신은 재렌더+`replaceChildren`으로 한다. "per-frame DOM 생성 금지·노드 풀"은 **"틱마다 씬 전체를 다시 만들지 않는다(변경 노드만 갱신)"**로 번역한다. 60fps·동시 노드 ≤40·transform/opacity 한정은 그대로 유지하고 M1에서 실측한다.

### B-6. 패럴랙스: `parallax.mjs` 부재 → **본 게임이 신규 작성** (스펙 §6-1, §14)
`src/parallax.mjs`가 없고 KTX 배경은 CSS 스크롤이라 추출 대상이 아니다. 안전길 배경도 격자 타일이라 옆스크롤로 못 쓴다(감사 ⑧).
→ 택배가 3레이어 패럴랙스를 **신규 작성**한다. 스펙이 정한 발동 조항대로 **총 LOC 상한 3,000**을 적용한다. 재사용은 `safety-route-art.mjs`의 오브젝트 SVG 일부와 `.route-pad` 모바일 밴드로 한정한다.

## C. 사용자 확인이 필요한 결정 2건

### C-1. 음성 73종(ko+en = mp3 146개) 발주
스펙 §10-3의 신규 보이스는 73종이다. 세기 음성 재사용으로 contingency 10종은 불필요(감사 ⑩)하므로 **정확히 73종 × 2언어 = 146개 mp3**를 edge-tts로 생성해야 한다. 이는 M4에서 **별도 네트워크 승인**이 필요하다(security.md §1). 참고로 이번 세션의 물감 게임은 41종×2=82개였다.
→ **감사 단계에서 결정할 일은 아니지만, M4 도달 전에 "73종을 다 만들 것인가, 줄일 것인가"를 확인받아 두는 편이 낫다.**

### C-2. 난이도 옵트아웃의 실제 형태
홈의 난이도 picker는 카드별이 아니라 **화면 상단 전역 UI**다. 스펙 §11이 요구한 "카드 포커스 시 난이도 UI 숨김"은 기존 홈 레이아웃을 건드리는 동작이라 **"기존 게임 무변경" 불변식과 마찰**한다.
→ 제안: **UI를 숨기지 않는다.** 대신 (a) 택배 게임은 `state.difficulty`를 읽지 않고(어떤 값이어도 동일), (b) 카드 진입 시 1회 음성 `no_diff`("이 게임은 바로 출발해요!")로 알린다. 이러면 홈 마크업·레이아웃 변경이 0이고 스펙의 의도(난이도 축 없음)는 그대로 달성된다.

- **구조적 충돌 없음** — 중단 사유 없음.
- 개정 6건(B-1~B-6)은 전부 "저장소 관행에 맞춘 최소 조정"이며 게임 설계의 재미·학습 축(엘리베이터 심장, 다중 정차 큐, 서프라이즈 엔진, 피날레 풀)을 하나도 건드리지 않는다.

| 1 | 택배차를 참고 이미지 형태로 | 노란 측면 트럭 폐기 → **흰색 캡오버 박스트럭**(앞유리 위 큰 눈 + 크롬 그릴 미소 + 파란 유리). 특정 캐릭터 복제가 아니라 그 형태(만화 차량 관용구)를 따르는 오리지널 도장이다. 파일 `src/delivery-truck-art.mjs` 신설(4방향 스프라이트). |
| 2 | 주행을 안전한 길찾기 식으로 | 옆스크롤·가속/브레이크·주행 봉투·오버런 보정을 **전부 폐기**하고 **격자 지도 + 방향키 4방향**으로 교체. 길찾기의 타일·카메라·미니맵·방향 패드 문법을 따른다. **부수 효과: `src/parallax.mjs` 신규 작성이 불필요해져 감사 B-6을 철회하고 LOC 상한을 3,000 → 2,800으로 원복.** 주차는 "존 칸에서 Space" 한 동작. |
| 3 | 엘리베이터 고도화 | 샤프트에 기계실·도르래·케이블·평형추·가이드레일·층별 승강장 문·**홀 랜턴**·피트를 추가. 우측은 평면 패널 대신 **승강기 안 원근 실내**(천장등·측벽 거울·핸드레일·바닥 반사·문 상부 층 표시기·열린 문틈의 복도)와 **실물 조작반(COP)**(브러시드 메탈·베젤 이중 버튼·점자 점·도트 표시기)로 재구성. 좌우 비율 60:40 → **38:62**. |
| 4 | 물건 종류 구분 전달 | 상자에 **종류**(과일·화장품·장난감·책)를 붙이고, 문 앞에서 수취인이 원하는 종류를 말하면 **←/→로 고르고 Space로 건넨다**. 새 phase `pick-parcel` + 새 키 0개(복도와 같은 키). 보이스 **73 → 79종**(kind_* 6종). 오답도 무벌칙(`kind_again` 후 재선택), 12초 무진행 시 `autopick`. |

**철회된 개정**: B-6(패럴랙스 신규 작성) — 지시 2로 불필요해짐. 총 LOC 상한 **2,800**.
