# SRT 실사 주행 모션 설계

## 목표

7번 `칙칙폭폭 기관사`의 실사 장면을 고정 사진에서 속도·가감속·정차 상태에
직접 반응하는 2.5D 주행 장면으로 바꾼다. 기존 95점 수준의 SRT 외형과 운전실
구도는 유지하면서, 역·선로·전신주·풍경이 실제 열차 진행 방향과 속도에 맞춰
움직여야 한다.

## 사용자가 체감해야 하는 결과

- 속도 0km/h에서는 모든 주행 레이어가 완전히 멈춘다.
- 가속하면 선로와 전신주가 먼저 빨라지고, 건물과 산은 상대적으로 천천히 흐른다.
- 200km/h 이상에서는 근경의 이동과 방향성 블러가 뚜렷해 고속 주행으로 읽힌다.
- 감속하면 모든 레이어가 같은 비율로 부드럽게 느려진다.
- 역은 먼 곳에서 접근해 정위치에 멈추고, 출발하면 뒤로 밀려난다.
- 운전실에서는 계기판은 고정되고 앞 유리 안의 선로와 시설물만 소실점에서 다가온다.
- 도시·평야·산·강·바다·터널은 각기 다른 풍경과 이동 단서를 가진다.

## 선택한 방식

### 실사 레이어 분리형 2.5D 합성

단일 완성 사진을 통째로 흔드는 방식은 사용하지 않는다. 장면을 다음 요소로
분리해 합성한다.

1. 하늘: 게임 위치의 0.01배로 이동하고 정차 시 고정
2. 원경: 산, 도시 스카이라인, 먼 구름
3. 중경: 건물, 숲, 강변 시설, 방음벽
4. 근경: 전신주, 표지판, 울타리, 승강장 기둥
5. 선로: 침목과 자갈의 가장 빠른 반복 이동
6. 바깥 화면의 열차와 운전실 화면의 프레임: 각 화면의 고정 기준점
7. 실제 계기와 교육 UI: 기존 상태 갱신을 그대로 유지

바깥 화면에서는 SRT 열차가 화면 중심 부근에 머물고 풍경이 오른쪽에서 왼쪽으로
흐른다. 운전실 화면에서는 투명한 전면창 영역 뒤로 선로와 환경이 소실점에서
화면 하단으로 확대되며 다가온다.

## 자산 구조

### 바깥 화면

각 환경은 반복 가능한 넓은 WebP 레이어를 제공한다.

- `sky`: 2560×720 이상, 수평 반복 가능
- `far`: 3840×720 이상, 좌우 이음새가 보이지 않는 파노라마
- `mid`: 3840×720 이상, 알파 채널을 가진 반복 가능한 띠
- `near`: 2560×720 이상, 전신주·울타리·표지판을 개별 DOM/SVG로 병행
- `track`: CSS/SVG 반복 패턴, 속도 변화에 즉시 반응
- `train`: 투명 배경 SRT 측면 실사 합성 자산

### 운전실 화면

- 운전실 프레임과 계기판은 투명 전면창을 가진 고정 WebP/PNG 레이어로 만든다.
- 전면창 뒤에는 환경별 원경·선로·전차선 레이어를 배치한다.
- 터널은 별도의 벽·조명 반복 레이어를 사용한다.

기존 완성 사진은 저사양 또는 신규 자산 로드 실패 시 사용하는 정적 실사 폴백으로
남긴다. 기존 SVG는 그 다음 단계의 최종 폴백이다.

## 속도 모델

단일 CSS 애니메이션 시간이 아니라 게임 상태의 실제 `state.v`를 정규화한 값을
장면에 전달한다.

```text
speedRatio = clamp(state.v / 300, 0, 1)
```

각 레이어의 이동량은 게임 위치 `state.x`를 기준으로 계산한다.

| 레이어 | 위치 배율 | 역할 |
|---|---:|---|
| 하늘 | 0.01 | 거의 고정된 기준 |
| 원경 | 0.06 | 산·도시의 먼 이동 |
| 중경 | 0.22 | 건물·숲·강변 이동 |
| 근경 | 0.85 | 전신주·울타리의 빠른 통과 |
| 선로 | 1.00 | 실제 진행량 기준 |

렌더러는 기존 `state.x`와 `state.v`에서 CSS 변수를 갱신한다. 위치 기반이므로 프레임이
잠시 느려져도 배경이 잘못된 지점으로 순간 이동하지 않는다. CSS transition은 두 상태
업데이트 사이만 보간한다.

## 주행 반응

### 가속

- 속도 1km/h부터 선로 이동을 시작한다.
- 80km/h 이상에서 전신주와 울타리 통과가 명확해진다.
- 160km/h 이상에서 근경 방향성 블러와 미세 차체 진동을 시작한다.
- 240km/h 이상에서 속도선과 전차선 진동을 추가하되 열차와 계기는 흐리지 않는다.

### 제동

- 레이어 이동 속도는 실제 속도 감소와 동시에 줄어든다.
- 강한 제동에서는 열차/운전실 기준 레이어가 짧게 앞으로 1~2% 쏠린다.
- 완전 정차 시 transition 잔여 이동을 제거해 배경이 미끄러지지 않는다.

### 터널

- 진입 직전 포털이 소실점에서 확대된다.
- 터널 내부 벽과 조명이 속도에 맞춰 반복된다.
- 출구에서는 기존 밝기 플래시를 유지하되 최대 투명도는 현재 안전 기준을 넘지 않는다.

## 역 접근과 정차

역은 단순 배경 교체가 아니라 위치를 가진 장면 객체로 취급한다.

1. 정차점 600m 전: 승강장 지붕과 역사가 원경에 나타난다.
2. 320m 전: 역명판, 승강장 기둥, 대기 친구가 식별 가능해진다.
3. 정차점 접근: 승강장이 열차 진행 반대 방향으로 이동한다.
4. 정위치 정차: 문 위치와 승강장 표식이 맞고 모든 역 레이어가 멈춘다.
5. 출발: 승강장과 역명판이 뒤로 빠르게 밀려난 후 일반 풍경으로 전환된다.

역 진입 중에는 일반 근경 장애물 스폰을 줄여 시선이 역명과 정차점에 모이게 한다.

## 환경별 모션 단서

- 도시: 건물·방음벽·교량 기둥의 강한 중경 이동
- 평야: 논밭·나무줄·전봇대가 긴 수평 흐름 형성
- 산: 먼 산은 느리고 가까운 절개지와 터널 입구는 빠르게 이동
- 강: 수면 반사와 교량 난간이 서로 다른 속도로 이동
- 바다: 수평선은 거의 고정하고 해안 방호벽과 표지판이 빠르게 통과
- 터널: 벽 조명 간격으로 속도를 가장 명확하게 표현

## 상태와 폴백

장면 상태는 다음 우선순위를 가진다.

1. `motion-ready`: 분리 실사 레이어가 모두 준비되어 동적 장면 사용
2. `realistic-ready`: 기존 완성 실사 이미지에 제한된 카메라 이동 사용
3. `fallback`: 기존 열차별 SVG 장면 사용

KTX에는 SRT 실사·모션 자산을 적용하지 않는다. KTX는 기존 전용 SVG 애니메이션을
유지한다. 자산 전환 실패 시 현재 보이는 정상 장면을 갑자기 지우지 않고 다음 안전한
단계로 내려간다.

## 접근성과 성능

- `prefers-reduced-motion: reduce`에서는 근경 블러·진동·속도선을 제거하고 위치 변화만
  낮은 빈도로 갱신한다.
- 변형은 `transform`과 `opacity` 위주로 처리해 레이아웃 재계산을 피한다.
- 동시에 움직이는 큰 래스터 레이어는 바깥 화면 최대 4장, 운전실 최대 3장으로 제한한다.
- 보이지 않는 뷰의 애니메이션은 일시 정지한다.
- 모바일에서는 근경 객체 수와 블러 강도를 줄이되 실제 속도와 정차 위치는 유지한다.

## 테스트 기준

### 모델 및 렌더러

- 0km/h에서 모든 모션 CSS 변수가 정지값이다.
- 속도가 증가할수록 레이어 이동률과 효과 단계가 단조 증가한다.
- 같은 `state.x`는 같은 레이어 위치를 만든다.
- 역 접근 거리별 상태가 600m, 320m, 정차, 출발 순서로 전환된다.
- KTX는 SRT 모션 자산을 요청하지 않는다.
- 분리 자산 실패 시 기존 정적 실사를 먼저 사용하고, 그것도 실패하면 SVG를 유지한다.

### 브라우저

- 1280×720 바깥 화면에서 열차는 선명하고 풍경·선로가 속도에 맞춰 이동한다.
- 1280×720 운전실에서 계기판은 고정되고 전면창 풍경만 이동한다.
- 844×390 모바일 가로 화면에서 잘림·가로 스크롤·조작부 겹침이 없다.
- 0→80→160→240→300km/h와 300→0km/h 변화가 육안으로 구분된다.
- 역 진입, 정위치 정차, 출발이 하나의 연속 장면으로 보인다.
- 콘솔 오류가 없고 큰 이미지의 반복 로드가 발생하지 않는다.

## 완료 기준

- 기존 실사 구도와 SRT 외형 적합도 95점 이상을 유지한다.
- 주행 중 정지 사진처럼 보이는 구간이 없다.
- 속도계 값과 배경 흐름의 방향·강도가 모순되지 않는다.
- 전체 자동 테스트와 데스크톱·모바일 시각 검증이 통과한다.
- 독립 검토에서 Critical/Important 문제가 남지 않는다.
