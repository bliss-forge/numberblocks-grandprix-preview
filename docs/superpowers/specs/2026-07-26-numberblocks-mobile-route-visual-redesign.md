# 넘버블럭스 안전길 PC 우선 시각 개선 설계

## 목적

안전길 게임의 교육 규칙과 32×16 지도 구조는 유지하면서, 지도를 화면에서 더 크게 보이게 하고 실제 동네 교통 환경처럼 읽히도록 장면을 개선한다. 먼저 PC 버전을 완성하고 사용자 확인을 받은 뒤, 승인된 PC 장면을 모바일에 맞게 반응형으로 확장한다.

## 구현 순서

### 1단계 — PC 버전

- 1280×720을 기준 화면으로 사용한다.
- 지도 확대, 축소된 방향키, 올바른 도로·차선·횡단보도·신호 위치, 골목 표현, 탑승자가 있는 킥보드·자전거, 닫힌 맨홀, 새 공사 차단봉을 모두 PC에서 먼저 완성한다.
- 자동 테스트와 PC 브라우저 QA를 통과한 결과를 사용자에게 보여준다.
- 사용자가 PC 장면을 승인하기 전에는 모바일 전용 레이아웃을 구현하지 않는다.

### 2단계 — 모바일 버전

- 승인된 PC 장면의 구조와 일러스트를 변경하지 않고 반응형 배치만 추가한다.
- 390×844 세로 화면과 640×360 가로 화면을 기준으로 검증한다.
- 모바일 단계에서 발견된 디자인 변경이 PC 화면을 퇴행시키지 않도록 PC 회귀 검증을 다시 수행한다.

## 확정된 방향

- 기존의 평면형 어린이 애니메이션 분위기를 유지한다. 입체 렌더링과 사실적인 사진 합성은 사용하지 않는다.
- PC 1단계는 7×5 카메라 시야를 유지한다.
- 모바일 2단계에서 세로 화면은 5×5, 가로 화면은 7×5 시야를 적용한다.
- 현재 플레이어 중심 카메라, 수집 순서, 횡단 규칙, 충돌 회피 규칙은 변경하지 않는다.

## 화면 구성

### 지도 영역

- 상단 안내와 점수 영역을 압축하고 지도 뷰포트가 나머지 가용 영역의 대부분을 차지하게 한다.
- 데스크톱에서는 지도 뷰포트가 가능한 범위에서 화면 너비의 약 92% 이상을 사용한다.
- 모바일 2단계에서는 좌우 최소 여백만 남기고 상단 안내 아래부터 하단 안전 여백까지 지도를 확장한다.
- 셀 크기는 가용 너비와 높이 중 더 작은 값으로 계산해 세로·가로 스크롤을 만들지 않는다.
- 카메라는 지도 경계가 허용하는 동안 플레이어를 정확한 중심 셀에 유지한다.

### 방향키

- 방향키는 지도 오른쪽 아래에 겹쳐 배치한다.
- 기본 상태는 작고 반투명하게 표시해 지도를 가리지 않는다.
- 터치, 키보드 포커스, 누름 상태에서는 대비와 불투명도를 높인다.
- 터치 목표 크기는 최소 44×44px을 유지한다.
- 방향키 포커스는 100ms 월드 갱신 중에도 유지되어야 한다.

## 교통 공간 표현

### 중앙 도로와 차선

- 중앙 4열은 왕복 2차선 도로다. 각 방향 차선은 2열 폭을 사용한다.
- 두 차선 사이에는 노란 중앙선을, 보도 경계에는 흰 가장자리선을 둔다.
- 차량은 서로 반대 방향으로 움직이고 자기 차선 중심을 유지한다.
- 차선 표시는 차량 진행 방향과 충돌하지 않으며, 불필요한 격자선은 약하게 처리한다.

### 횡단보도와 신호등

- 위·아래 두 횡단보도는 도로 진행 방향에 직각으로 배치한다.
- 횡단보도 줄무늬는 중앙 4열 전체를 가로지른다.
- 신호등은 도로 한가운데가 아니라 각 횡단보도 옆 보도 모서리에 배치한다.
- 위·아래 횡단보도에서 카메라 안에 신호가 최소 하나 이상 보여야 한다.
- 모든 신호 표시는 하나의 논리 상태를 공유하고 색상 외에도 상태 라벨을 제공한다.

### 골목과 보행 공간

- 골목은 도로와 같은 아스팔트로 그리지 않는다.
- 한 칸 폭 골목은 밝은 베이지색 보도블록, 낮은 경계석, 건물 벽과 출입구로 좁은 생활 골목처럼 표현한다.
- 두 칸 폭 보행로는 더 열린 보행 공간으로 구분하며, 차량 차선 표시는 사용하지 않는다.
- 공사로 막힌 골목은 다른 골목으로 우회할 수 있다는 경로 가독성을 유지한다.

## 이동 물체와 장애물

### 킥보드와 자전거

- 빈 킥보드와 빈 자전거가 스스로 움직이지 않는다.
- 각 이동 물체에는 헬멧을 쓴 어린이 탑승자를 결합한 하나의 평면 일러스트를 사용한다.
- 기존의 느린 왕복 이동, 플레이어 앞 정지, 반전, 비충돌 규칙은 유지한다.
- 탑승자와 이동 수단은 방향 전환 시 함께 뒤집히며 이동 방향이 명확해야 한다.

### 맨홀

- 열린 구멍이나 주변 경고 광선처럼 보이는 장식을 제거한다.
- 바닥과 수평인 닫힌 원형 주철 덮개로 표현한다.
- 원형 테두리와 단순한 격자 무늬만 사용하고 보행 경로의 한 칸 장애물이라는 판독성은 유지한다.

### 공사 차단봉

- 첨부 이미지는 안전 장비의 구조와 색상만 참고한다. 원본 사진, 워터마크, 체크무늬 배경은 사용하지 않는다.
- 노랑·검정 사선 차단판, 주황·흰색 기둥 두 개, 넓은 받침으로 구성한 자체 평면 CSS 일러스트를 만든다.
- 골목 한 칸을 완전히 막는 폭으로 배치하되 주변 건물과 겹치지 않는다.

## 접근성 및 성능

- 장면의 안정적인 DOM 구조를 유지하고 월드 갱신 시 필요한 동적 속성만 변경한다.
- 신호, 차량 방향, 장애물, 장소는 접근 가능한 한국어 라벨을 가진다.
- 모션 감소 설정에서는 장식 애니메이션을 끄고 게임의 논리 이동은 유지한다.
- 외부 이미지 요청 없이 기존 로컬 자산과 CSS 도형만 사용한다.

## 검증 기준

- PC 승인 전 검증 — 1280×720: 7×5 시야, 확대된 지도, 반대 방향 차량, 양쪽 신호 위치, 8개 장소, 키보드 이동을 확인한다.
- PC 승인 후 모바일 검증 — 390×844: 5×5 시야, 플레이어 중심, 지도 무스크롤, 축소 방향키, 터치 이동을 확인한다.
- PC 승인 후 모바일 검증 — 640×360: 7×5 시야, 낮은 높이에서 지도와 조작키가 겹치지 않는지 확인한다.
- 킥보드와 자전거 각각 탑승자 표시, 왕복, 정지, 반전, 비충돌을 확인한다.
- 닫힌 맨홀과 공사 차단봉이 별개의 장애물로 즉시 구분되어야 한다.
- 위·아래 횡단보도 어느 쪽에서도 신호등을 플레이어 이동 전에 관찰할 수 있어야 한다.
- 전체 자동 테스트와 `git diff --check`가 통과해야 한다.

## 범위 밖

- 게임 규칙, 점수, 음성, 난이도 체계 변경
- 지도 크기 32×16 또는 14:4:14 구역 비율 변경
- 외부 사진이나 워터마크가 있는 이미지의 직접 사용
- 새로운 장애물 종류나 실패 패널티 추가
