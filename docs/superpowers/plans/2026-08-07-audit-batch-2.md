# 감사 후속 배치 2 — 남은 18건 실행 계획

**출처:** 2026-08-06 전 영역 감사(7번 KTX 제외, 에이전트 13, 발견 24건 중 반증 통과 22건).
1차 배치(높음 4건 + 물감 회귀 2건)는 `c171517`로 배포 완료. 이 문서는 남은 **보통 10건 ·
낮음 8건**을 묶어 순서와 최소 수정 방향을 못박는다.

**원칙:** 한 배치 = 한 브랜치 = 한 번의 `npm test` 초록 + 두 뷰포트 실렌더 확인.
아이 체감이 큰 것부터, 그리고 같은 파일을 만지는 것끼리 묶는다. 새 자산·새 의존성 없음.

## B2-1 소리와 안내 — 글 못 읽는 아이의 유일한 채널 (4건)

가장 먼저 한다. 이 넷은 "아이가 안내를 못 받는" 부류라 체감이 가장 크다.

### 1. 안전 안내 음성이 0.15초만 반복된다 (SAFETY-2 · 보통)
- **파일:** `src/app.mjs:800-806`(cue 재생), `:2232`(키보드 반복 경로)
- **수정:** 같은 `voiceKey`가 재생 중이면 `audio.cancel()` + 재생을 건너뛴다. 홀드 가드
  하나만 넣으면 180ms 연타 경로가 남으므로, **재발화 억제**가 두 경로를 한 번에 덮는다.
  구현 위치는 `audio` 래퍼가 아니라 안전길 cue 재생부 한 곳(모드 전용 정책이므로).
- **테스트:** 같은 cue를 연속 두 번 발생시켰을 때 `playPrompt` 호출이 1회인지
  (오디오 매니저를 스텁으로 주입하는 `tests/audio-manager.test.mjs` 패턴 재사용).

### 2. take-the-bus 안내에 음성이 없다 (SAFETY-3 딸림 · 보통)
- **파일:** `src/safety-route-controller.mjs:33-36`(`voiceKey: null`)
- **수정:** 새 키 `safety-take-the-bus` 추가 → 매니페스트 + `scripts/generate_voice_pack.py`
  문구 등록. **mp3 생성은 네트워크(edge-tts)라 별도 승인 필요** — 승인 전에는 기존
  `safety-bus-stop` 계열 키로 임시 연결하지 않고 자막만 유지한다(잘못된 음성이 더 나쁘다).
- **테스트:** `tests/voice-assets.test.mjs`에 키 추가(생성 후).

### 3. 역 안내방송 음원 4개 누락 (SUBWAY-4 · 낮음)
- **파일:** `src/subway-sound-manifest.mjs:25-28`
- **수정:** 모란·가양·국회의사당·봉은사는 실음원이 없다 → `stationSoundSrc`가 없는 역에
  `null`을 주고 호출부가 역이름 TTS로 폴백하게 한다(현재는 404 후 무음).
- **테스트:** `SUBWAY_LINES`의 모든 비가족역에 대해 "실음원 있음 또는 폴백 키 있음"을
  단정하는 계약 테스트. 실음원 파일을 나중에 넣으면 자동으로 우선 재생된다(기존 구조).

### 4. 물감 혼합 수식 자막이 채색보다 먼저 사라진다 (COMP-3 · 보통)
- **파일:** `src/app.mjs:686`(`showHint` 1300ms 고정)
- **수정:** `showHint(message, holdMs = 1300)`로 유지 시간을 인자화하고, 혼합 수식만
  `PAINT_AUTO_MS + 채색 연출`까지(약 3.2초) 유지한다. 다른 호출부는 기본값 유지.
- **테스트:** 인자 없는 호출이 1300ms를 쓰는지 + 물감 혼합 자막이 채색 시점 이후까지
  남는지(브라우저 계측 1건, 기존 하네스 재사용).

## B2-2 학습 유도 — 아이가 막히거나 헛걸음하는 곳 (4건)

### 5. add·sub·mul에 화면 힌트 에스컬레이션이 없다 (MATH-4 · 보통)
- **파일:** `src/app.mjs:1606-1614`(`mode === "count"` 조건 안에만 있다)
- **수정:** 조건을 모드 무관으로 넓힌다. 2회 오답 → 피연산자 블록에 `hint-groups`류
  시각 묶음, 4회 → 문구에 자릿수 단서("스물 몇 개예요"). 음성 격려(retry-1..3)는 이미
  모드 무관으로 동작하므로 손대지 않는다.
- **테스트:** `wrongCount` 2·4에서 힌트 문구·클래스가 바뀌는지(브라우저 1건) +
  count 기존 동작 회귀.

### 6. 버스 난이도 발자국이 정류장 반대를 가리킨다 (SAFETY-3 · 보통)
- **파일:** `src/app.mjs:511-545`(화면 안내용 target)과 `:710-716`(`safetyTarget`)
- **수정:** 발자국·화살표·거리·배너가 모두 `safetyTarget()` 한 값을 쓰게 통일.
  반증에서 드러난 근본 원인 — 버스 모드에서 `findSafetyPath`가 도보 금지인 횡단 칸을
  경로로 잡는 것 — 도 함께 막는다(busMode면 crossing 칸을 경로 후보에서 제외).
- **테스트:** steady 여러 시드에서 "발자국 첫 칸이 정류장 방향" + "경로에 crossing 칸 없음".

### 7. 일반 여정이 보너스 가족역에서 출발한다 (SUBWAY-2 · 보통)
- **파일:** `src/subway-journey.mjs:174-188`(`journeyCandidates`)
- **수정:** 가족 여정이 아닐 때 `line.family` 노선을 후보에서 제외(한 줄).
- **테스트:** 시드 0~199 × 목적지 10곳에서 출발역이 실제 노선에만 있는지 단정.

### 8. 무지개 7색이 쉬움·차근차근에서 도달 불가 (PAINT-3 · 낮음)
- **파일:** `src/paint-play-data.mjs:102-109`, `src/paint-play-scene.mjs:149-153`
- **수정(추천):** `RAINBOW_COUNT` 고정 7을 버리고 **표기를 `n/라운드 수`**로 바꾼다
  (쉬움 4/5색처럼). 더불어 `buildRounds`가 이미 나온 색을 뒤로 미뤄 서로 다른 색을
  우선 뽑게 해 도전에서 7색 확률(현재 2.9%)을 올린다. 라운드 수를 늘리는 방향은
  4~6세 집중 시간을 넘기므로 택하지 않는다.
- **테스트:** 난이도별 "완주 시 표기 상한 = 라운드 수" + 도전 7색 도달 가능 시드 존재.

## B2-4 위생과 테스트 공백 (3건)

### 16. 안전길 숫자키마다 uncaught TypeError (통합 · 낮음)
- **파일:** `src/app.mjs:1620`
- **수정:** `if (state.phase !== "playing" || !state.problem) return;` 한 줄.
- **테스트:** 기존 브라우저 테스트의 safety 케이스에 "투어 스킵 후 숫자키 → pageErrors 0"
  단정 추가. 이 한 줄이 없어서 CORE-1이 초록을 뚫었다(반증에서 좁혀진 진짜 공백).

### 17. 홈 세로 잘림 계약 테스트가 항상 통과 (HOME-4 · 낮음)
- **파일:** `tests/mobile-games-browser-layout.test.mjs:226`
- **수정:** `documentElement.scrollHeight` 비교를 버리고 **실측 사각형**으로 판정 —
  모든 카드 `bottom <= innerHeight`, 넘치면 `#home.scrollHeight > clientHeight`.
  `mediaBlock()`이 같은 마커의 모든 블록을 이어 붙여 검사하게 고친다(마지막 선언이 이김).

### 18. 오답 토스트가 축하 화면과 동시 표시 (MATH-3 · 낮음)
- **파일:** `src/app.mjs:1564`(`celebrate`)
- **수정:** `clearTimers`에서 토스트 타이머를 끌 때 `.show` 제거까지 한 곳에서 처리.

### 보류: CSS 캐시 버스팅 토큰 (CORE-4 · 낮음)
- 테스트 2개가 정확 문자열을 못박아 갱신을 막고 있다는 사실은 확인됐지만, **스타일이
  실제로 깨진 증거는 없다**(미확인 가설). B2-3에서 `styles.css`를 손대는 김에
  테스트를 느슨하게(`?v=` 존재 + 로드 순서) 바꾸고 토큰을 한 번 올린다 — 별도 항목으로
  두지 않고 그 배치에 얹는다.
